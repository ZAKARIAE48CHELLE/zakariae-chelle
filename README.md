# Zakariae Chelle — Portfolio

A static portfolio (HTML / CSS / vanilla JS) plus a **local-only back office** to edit it without touching code.

```
front/           ← the ONLY thing that gets deployed (GitHub Pages)
  index.html, config.js, i18n.js, diagrams.js   generated by the back office — don't edit by hand
  styles.css, script.js, diagram.js              hand-written front-end
  assets/ (fonts, favicon, share image)   resources/CV/ (PDFs)
data/
  portfolio-data.json    ← single source of truth for all content (+ translations)
  .backups/              ← automatic backups, git-ignored
admin/                   ← back office (never deployed)
  server.js              local server (127.0.0.1 only, token-protected)
  lib/                   builder, validation, translations tracking, store, git
  template/              index.template.html — page layout with {{placeholders}}
  public/                admin UI
  test/run.js            `npm test`
scripts/                 start-admin.bat | .ps1 | .sh
.github/workflows/       pages.yml — deploys front/ only
docs/                    portfolio enhancement documentation
```

## Use the back office

Needs [Node.js](https://nodejs.org) 18+. No `npm install` — there are zero dependencies.

- Windows: double-click `start-admin.bat` (or `scripts/start-admin.bat`)
- macOS / Linux: `./scripts/start-admin.sh`
- or `npm run admin`

A browser tab opens on a private link (`http://127.0.0.1:3333/?t=…`). The link contains a random token that changes every time you start it.

Workflow: edit → **Save & rebuild** (regenerates `front/`, keeps a backup) → check **Live preview** → **Publish** (commit + push).

What you can edit: profile, hero, about, quick facts, counters, hero pipeline, technology marquee, SEO tags, CV PDFs, featured projects (with a live architecture-diagram editor), more projects, skills, experience, education, and FR / ES / AR translations (with missing / outdated tracking). Every list supports reorder, hide, duplicate and delete. **History & restore** loads any of the last 50 backups back into the editor.

## Security model (why this is safe to leave on your machine)

The back office is **never deployed** and never listens on the network: it binds to `127.0.0.1` only. On top of that: a per-run secret token (HttpOnly, SameSite=Strict cookie), Host-header check against DNS rebinding, same-origin + JSON/PDF content-type required for every change (CSRF), no CORS, a strict CSP, traversal-safe file serving, git run without a shell, PDF magic-number and size checks, optimistic locking (no silent overwrite if the file changed on disk) and atomic writes. Run `npm test` to verify.

Because it only exists on the machine, there is no password: whoever can run it already has the files.

## Deploy to GitHub Pages

1. Push the repository to GitHub.
2. In your repo: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. From then on, every push to `main` that touches `front/` deploys **only `front/`**. The admin tool, data file and backups are never published.

## Good to know

- Don't edit `front/index.html`, `config.js`, `i18n.js`, `diagrams.js` by hand: the next build overwrites them. Layout changes go in `admin/template/index.template.html`; styling in `front/styles.css`.
- Each item has a permanent internal id (shown as a small chip). Translations are linked to that id, so reordering or renaming never breaks them.
- Run the site on its own: `npm run serve` → http://localhost:8000
